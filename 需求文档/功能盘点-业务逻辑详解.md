## 13. 设备数据 — DeviceDataController

标准 CRUD + 导出。

**数据写入链路**（非 Controller 触发）：

```
MQTT设备 → IoT平台 → AMQP → AmqpClient.processMessage()
  ├─ 解析 JSON: notify_data.body.services[]
  ├─ 查本地 Device 表确认设备存在
  ├─ 遍历 services：每个物模型属性生成一条 DeviceData
  ├─ saveBatch(list) → MySQL
  └─ Redis HSET iot:device_last_data {iotId} JSON(list)
```

> **键逻辑**：一次上报可含多个物模型（如烟雾报警器同时上报温度/湿度/烟雾），每条物模型属性生成一条 DeviceData。Redis 使用 **Hash 覆盖写**，一个设备只保留最新一次的全部上报数据。

## 14. 报警规则 — AlertRuleController

| 接口 | 业务逻辑 |
|------|---------|
| `/nursing/alertRule/list` | 分页查询，支持按规则名称/功能名称/产品ID精确筛选 |
| `/nursing/alertRule` | POST 新增：`status` 默认禁用(0)，支持启用。一条规则指定一个产品+一个物模型+一个运算符+一个阈值 |
| `/nursing/alertRule/{id}` | PUT 修改 + 单条查询 |
| `/nursing/alertRule/{ids}` | DELETE 批量删除 |

**规则字段含义**：

| 字段 | 说明 |
|------|------|
| `alert_data_type` | 0=老人异常（通知护理员）1=设备异常（通知行政） |
| `operator` | 运算符：`>` / `<` / `>=` / `<=` / `==` |
| `value` | 阈值 |
| `duration` | 持续周期：连续异常 N 次才触发 |
| `alert_effective_period` | 生效时段：格式 `00:00:00~23:59:59`（支持跨夜） |
| `alert_silent_period` | 沉默周期（分钟）：触发后 N 分钟内不重复报警 |
| `iot_id` | 默认 `-1`（该产品全部设备） |
| `product_key + function_id` | 匹配条件：设备数据的产品+物模型必须完全吻合 |

## 15. 报警数据 — AlertDataController + AlertJob

### 15.1 报警执行流程（AlertJob + AlertRuleServiceImpl）

```
定时触发 (Quartz: cron=0 * * * * ?  每分钟整点)
  │
  ├─ loadRules()
  │   SELECT * FROM alert_rule WHERE status=1
  │
  ├─ loadDeviceData()
  │   Redis HGETALL iot:device_last_data
  │   → 反序列化为 List<DeviceData>
  │
  └─ evaluateRule(每条DeviceData × 每条AlertRule)

      ① 生效时段判断 isInEffectivePeriod()
         │ 解析 "00:00:00~23:59:59" (支持跨夜 "22:00:00~06:00:00")
         │ 当前时间不在区间 → clearTriggerCount() → skip
         │
      ② 阈值判断 isThresholdExceeded()
         │ dataValue:String → Double.parseDouble → 比较 rule.operator + rule.value
         │ 未达阈值 → clearTriggerCount() → skip
         │
      ③ 沉默周期检查 isInSilentPeriod()
         │ Redis GET alert:silence:cycle:{iotId}:{ruleId}
         │ 有值(沉默中) → skip
         │
      ④ 异常计数 INCR alert:trigger:count:{iotId}:{ruleId}
         │
      ⑤ 持续周期判定
         │ count < rule.duration → 继续累计(不等)
         │ count >= rule.duration →
         │   ├─ DEL 异常计数
         │   ├─ SETEX 沉默周期 TTL=rule.alertSilentPeriod(分钟)
         │   └─ 触发报警
```

### 15.2 什么时候报警

| 条件 | 说明 |
|------|------|
| 产品+物模型匹配 | `productKey == rule.productKey AND functionId == rule.functionId` |
| 当前时间在生效时段内 | 解析 `00:00:00~23:59:59` |
| 数值超过阈值 | `dataValue operator rule.value`（如 30 < 65 → 触发） |
| 不在沉默期内 | Redis key `alert:silence:cycle:{iotId}:{ruleId}` 不存在 |
| 累计次数 ≥ 持续周期 | 例如 duration=3 需连续 3 分钟异常才触发 |
| 数据上报时间 ≤ 1分钟前 | 过滤历史数据 |

### 15.3 什么时候静默

| 条件 | 结果 |
|------|------|
| 报警触发后 | `SETEX alert:silence:cycle:{iotId}:{ruleId} "1" TTL分钟`，TTL = `alert_silent_period`（默认 5 分钟） |
| 沉默期内 | 即使数据异常也不生成新报警 |
| 沉默期到期 | Redis key 自动过期，可再次触发报警 |

### 15.4 通知人路由

```
alertDataType==0 (老人异常):
  ├─ locationType==0 (随身设备):
  │   accessLocation=elderId → nursing_elder → 护理员userId
  ├─ locationType==1 AND physicalLocationType==2 (床上设备):
  │   accessLocation=bedId → elder.bed_id → nursing_elder → 护理员userId
  └─ 其他: 无老人绑定

alertDataType==1 (设备异常):
  └─ SysUserRoleMapper.selectUserIdByRoleKey("administrator") → 行政人员

所有人追加: selectUserIdByRoleKey("admin") → 超管

→ 去重 → saveBatch(每人一条AlertData, status=0待处理)
```

## 16. AI 对话 — ChatController

### 16.1 对话流程

```
POST /ai/chat {prompt, chatId?}
  │
  ├─ 新会话: INSERT AiConversation → 返回 conversationId
  ├─ 已有会话: 
  │   ├─ ChatMemory.get() → Redis LRANGE chat:memory:{id} 0 -1
  │   └─ 若为空: DB加载全部历史 → JSON反序列化 → Message对象 → add到Redis
  │
  ├─ ChatMemory.add(当前用户消息)
  ├─ ChatClient.call() ← 全量历史作为上下文发送LLM
  ├─ ChatMemory.add(AI回复)
  ├─ DB: INSERT AiMessage(用户消息) + INSERT AiMessage(AI回复)
  └─ 返回 {chatId, content}
```

### 16.2 会话记忆存储（RedisChatMemoryServiceImpl）

| 操作 | Redis 命令 | 说明 |
|------|-----------|------|
| add | `RPUSH chat:memory:{id} [json...]` | 追加消息 |
| get | `LRANGE chat:memory:{id} 0 -1` | **全量读取**（性能瓶颈） |
| clear | `DEL chat:memory:{id}` | 删除会话记忆 |

### 16.3 历史会话管理

| 接口 | 逻辑 |
|------|------|
| GET `/ai/history` | Redis 查 `ai:conversations:user:{userId}` (TTL 24h)，未命中→DB 查→写 Redis |
| GET `/ai/history/{id}` | Redis 查 `ai:conversation:messages:{id}` (TTL 24h)，未命中→DB→写 Redis |
| DELETE `/ai/history/{id}` | 事务删除 DB 会话+消息 + 清除 Redis ChatMemory + 清除 Redis 缓存 |

## 17. 健康评估 — HealthAssessmentController

### 17.1 评估流程

```
POST assessmentData(ElderAssessmentDto)
  │
  ├─ ① saveOrUpdateHealthAssessment()
  │   新增/更新：健康评估基本信息 + 数据采集表
  │   (基本信息/健康评估/日常活动/精神状态/感知沟通/社会参与 → JSON 存 DB)
  │
  ├─ ② AI 调用 1: 能力等级评估 (同步)
  │   Prompt: 6 个能力维度 + 评估规则1(分级标准) + 规则2(升级条件)
  │   返回: preLevel(初步等级) + finalLevel(最终等级) + reason(升级理由)
  │   耗时: ~5s
  │
  ├─ ③ 下载 PDF 体检报告 (OSS 同步下载)
  │
  ├─ ④ PDF 解析 (PagePdfDocumentReader 同步)
  │
  ├─ ⑤ AI 调用 2: 体检报告分析 (同步)
  │   Prompt: 3000+ token 指令 + 体检报告全文
  │   返回: healthScore(0-100) + riskLevel(健康/提示/风险/危险/严重危险)
  │         + abnormalData(异常分析) + systemScore(8大系统打分) + summarize(总结)
  │   耗时: ~10s
  │
  ├─ ⑥ AI 调用 3: 综合建议 (同步, 依赖①②结果)
  │   Prompt: 总结 + 异常 + 能力等级 → 综合推理
  │   返回: core_suggestion / recommended_care_level / diet_suggestion 等 9 项
  │   耗时: ~8s
  │
  ├─ ⑦ 保存评估报告 (HealthAssessmentReport)
  │   含所有 3 次 AI 返回结果 + coreSuggestion(healthScore≥60→建议入住)
  │
  └─ ⑧ 更新评估状态: evaluation_progress=1(已完成)

总耗时: ~23s (三次串行 LLM 调用)
```

### 17.2 评估等级规则

| 初步等级 | 条件（规则1） |
|---------|------------|
| 能力完好 | 日常生活0 + 精神0 + 感知0 + 社会0或1 |
| 轻度失能 | 日常0但精神/感知≥1 或 社会=2；或日常=1 |
| 中度失能 | 日常=1且精神/感知/社会≥2；或日常=2 |
| 重度失能 | 日常=3 或 全部=2 或 日常=2且一项=3 |

**升级条件（规则2）**：认知障碍/痴呆 → +1级；近30天≥2次跌倒/噎食/自杀/走失 → +1级；昏迷 → 直接重度

| Key | 结构 | 用途 | TTL |
|-----|------|------|-----|
| `iot:device_last_data` | Hash | 设备最新上报数据（field=iotId） | 永久 |

| `ai:conversations:user:{userId}` | String | 用户会话列表缓存 | 24h |
| `ai:conversation:messages:{id}` | String | 会话消息缓存 | 24h |
